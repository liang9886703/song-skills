# Skill 质量校验官（生产级）

## 核心指令

你是一个 **元级 Skill**，职责是校验其他生产级 Skill 的质量。你不解决具体业务问题，而是确保「Skill 本身写得足够好」。

核心原则：用结构化的检查清单代替模糊的"请自查"。

## 核心能力

| 维度 | 权重 | 检查项数 | 说明 |
|------|------|----------|------|
| 结构完整性 S | 25% | 4 项 | Skill 是否包含必要组成部分及引用文件是否真实存在 |
| 逻辑一致性 L | 20% | 4 项 | 步骤之间是否矛盾、重复、遗漏 |
| 鲁棒性 R | 20% | 5 项 | 异常情况是否有兜底、降级、容错 |
| 可执行性 E | 15% | 4 项 | 指令是否清晰、无歧义、可操作 |
| 无冗余 D | 10% | 2 项 | 是否有重复内容、临时代码、过时逻辑 |
| 可维护性 M | 10% | 2 项 | 配置集中度与修改便利性 |

## 触发条件

| 场景 | 触发方式 | 预期行为 |
|------|----------|----------|
| 用户希望检查某个 Skill 的质量 | 说"帮我检查/校验/审查 xxx 技能/Skill 的质量" | 自动定位目标 Skill → 全量采集 → 执行 21 项检查 → 输出标准质量报告 |
| 用户完成 Skill 编写后要求验收 | 说"帮我看看这个 skill 行不行 / 上线前验收 / 写完了帮我查一遍" | 对新完成的 Skill 进行全面质量检查，输出含评级的验收报告 |
| AI 工具修改了某个 Skill 后回归验证 | 说"AI 改完了再查一遍 / 帮我看看改得怎么样" | 重新执行完整检查流程，输出变更后的质量报告 |
| 多个协作方需要对齐 Skill 质量标准 | 说"检查这个技能有没有问题 / 帮我 review 一下" | 按统一标准执行校验，确保跨协作方质量一致 |

## 工作流程

> **🔧 兼容性提示**：以下采用 ASCII Tree 风格绘制，含少量 UTF-8 框线字符（如遇显示错位，请切换等宽字体或 Markdown 预览模式）。

```
Step 1: 定位目标 Skill
│-- 方式A：在 extensions_index 检索对应 Skill
│-- 方式B：直接读取用户提供的路径
└-- Fallback -- A/B 均失效时：
    │-- 向用户确认正确路径
    └-- 仍无法获取 → 终止并输出《无法定位目标》简报

                    ↓

Step 2: 全量采集
│-- 必读：SKILL.md（主体）
│-- 选读：scripts/*.py/*.sh
│-- 选读：references/*.md
└-- 选读：config/*.*
    [提醒] 大文件先 wc -l 再分批读

                    ↓

Step 2.5：脚本语法粗筛（LLM 目视·非精确 AST）
│-- .py 文件重点：
│     • 调用的外部库是否有对应 import 声明？
│         （例：代码中有 requests.get()，顶部需含 import requests）
│     • () [] {} 三类括号是否成对闭合
│     • 同一代码块内未混用空格和 Tab
└-- .sh 文件 ≥1 行 shebang
    [声明] 非精确AST分析，不能替代 flake8/pylint；
           权限不足时标【未验证】

                    ↓

Step 3：逐项检查（21项指标，详见 references/checklist-details.md）
└-- 每条判定 ✅通过 / ❌不通过
    ❌ 项记录：问题 + 位置 + 修复建议

                    ↓

Step 4：计算综合得分
└-- Σ(维度通过率 × 维度权重) → 加权总分

                    ↓

Step 5：输出标准报告
└-- Markdown 格式存入产出物目录
    .ark/output/skill_quality_日期/
```

## 全局约束

1. **只做诊断不做修改**：本 Skill 只出报告，不直接改被检 Skill 的任何文件。如需修复由用户决定。
2. **基于实际内容评判**：必须先完整阅读 SKILL.md 及关联脚本后再打分，不得凭印象猜测。若因权限无法读到某些脚本文件，在报告中标注为「未验证」而非默认通过。
3. **客观量化**：每个不通过项必须有具体的原文引用作为证据，禁止模糊表述。

## 检查项一览

详细通过标准、典型缺陷和检查方法见 `references/checklist-details.md`。以下是 21 项检查的概要：

| 维度 | 编号 | 检查项 |
|------|------|--------|
| 结构完整性 S | S01 | name & description 存在且合规 |
| | S02 | 全局约束/铁律章节 |
| | S03 | 工作流程总览（流程图或步骤概览） |
| | S04 | 引用文件真实存在性验证 |
| 逻辑一致性 L | L01 | 步骤间数据流是否衔接 |
| | L02 | 超时/重试配置是否统一 |
| | L03 | 步骤间循环依赖检测（DAG） |
| | L04 | 条件分支覆盖全部可能路径 |
| 鲁棒性 R | R01 | 外部接口调用失败降级方案 |
| | R02 | 数据为空/null 兜底展示 |
| | R03 | 关键字段缺失默认值 |
| | R04 | 操作超时处理机制 |
| | R05 | 单模块失败不阻断整体流程 |
| 可执行性 E | E01 | 指令措辞唯一确定、无歧义 |
| | E02 | 关键输出格式有示例 |
| | E03 | Shell/脚本命令完整带参数 |
| | E04 | 条件数值阈值明确定量 |
| 无冗余 D | D01 | 同一语义规则仅在单一位置出现 |
| | D02 | 已清除临时标记和遗留调试逻辑 |
| 可维护性 M | M01 | 运行时可变配置集中在固定区域 |
| | M02 | 同一配置值只需在一处修改 |

## 错误处理

本 Skill 在执行校验过程中可能遇到以下异常情况：

| 场景 | 处理方式 |
|------|----------|
| 目标 Skill 路径不存在 | 向用户确认正确路径；反复无法获取则终止并输出《无法定位目标》简报 |
| 权限不足无法读取文件 | 在该项检查结果中标注「🚮 未验证」而非跳过，汇总时计入未验证统计 |
| 脚本文件内容为空或格式损坏 | 标注文件状态，尝试部分读取；完全不可读时标注「无法读取」 |
| Step 2.5 脚本语法粗筛中检测到明显错误 | 报告具体行号和错误类型，不阻断后续检查流程 |
| R 维度全项不适用（纯提示词型 Skill） | 标记为「➖ 不适用」，分子分母同时扣减，不入总分 |

> **原则**：非关键模块的检查失败不阻断整体校验流程；所有异常均在报告中如实记录。

## 发布后清理

`oneskill create/update` 以及 `dodo_cli extension publish` 执行后，平台 CLI 会自动在技能目录生成 `.dodo_managed.json` 缓存文件。

**每次发布/同步完成后，必须最后执行一次清理**，再运行平台质量扫描，否则一定报"存在隐藏文件"：

```bash
# 完整操作流程：
bash scripts/pre-publish-cleanup.sh    # 1️⃣ 发布前清理
oneskill create ...                     # 2️⃣ 发布到 OneTool
bash scripts/pre-publish-cleanup.sh    # 3️⃣ oneskill 重建了，再清理
dodo_cli extension publish ... --zip    # 4️⃣ 同步个人技能库（如需要）
bash scripts/pre-publish-cleanup.sh    # 5️⃣ dodo_cli 又重建了，最后清理一次！
```

> ⚠️ **关键原则**：清理是**最后一步**。任何平台 CLI 操作（oneskill / dodo_cli）后都必须补一次清理，再去跑质量扫描。

脚本仅删除临时/缓存文件，不会修改 `SKILL.md`、`scripts/`、`references/` 等核心文件。

## 综合结论判定规则

加权总分 = Σ(维度_i 通过率 × 维度_i 权重)

| 加权总分 | 结论 | 含义 |
|----------|------|------|
| ≥ 85% | ✅ 通过 | 可以上线 |
| 60%~84% | ⚠️ 有条件通过 | 修复严重问题后上线 |
| < 60% | ❌ 不通过 | 不建议上线，需重构 |

补充否决规则：
- 若鲁棒性(R)维度通过率 < 40%，无论总分如何，结论强制为 ❌ 不通过
- 若有任何一项必过项完全没有实现痕迹（不是做得不好而是完全缺席），该维度该项判 ❌ 并升级至总体评价
- **➖ 不适用项处理**："➖" 标记的检查项仅在被检 Skill 涉及相关行为时才生效；
  - "➖" 项从分子/分母同时扣减；
  - 若某维度所有项均为 N/A，该维度不计入评分

## 输出格式

输出为 Markdown 标准质量报告，包含：综合结论、各维度通过率及加权贡献、21 项明细、问题清单（含证据引用）、修复优先级排序、总体评价。完整模板见 `references/report-template.md`。

报告存入产出物目录 `.ark/output/skill_quality_{日期}/`。

# 技能发现、安装与 Skillshare 管理

维护个人主仓库 `song-skills`，使用 `skillshare` 将技能分发到当前机器配置的 AI 工具。安装、来源登记、上游更新和本机同步都以主仓库为准。

## 中文约定与目录

- 用户自己编写的技能使用中文，包括 `description`、正文及配套说明；本技能也遵守此约定。目录名、`name`、命令和代码标识保留必要的英文。第三方技能保留原文和署名，保留已有中文适配。
- 读取当前生效的 skillshare 配置，通过 `sources.skills` 找到真实源目录；本机配置为 `/Users/zisongliang/code/song-skills/skills`，其他机器以各自配置为准。
- 每个技能放在 `skills/<技能名>/SKILL.md`，支持文件按原结构放在该目录内。不要把旧的 `~/.config/skillshare/skills/` 或工具目标目录当成主仓库。
- 读取主仓库 README、Git remote 和工作区差异；保留其他任务的修改。遵守本地技能的发布范围，本仓库 `baidu*` 技能仅留本地，不提交到 GitHub。

## 查找与推荐技能

先检查本地已有技能。用户指定来源时使用该来源；未指定时，公开通用技能从 skills.sh 查起，GitHub / Hub 补充，企业业务技能优先用 OneSkill；旧内网目录仅在已配置或明确指定时使用。OpenAI 官方精选目录作为官方来源筛选，不视作独立技能生态。

### 意图分析与推荐逻辑（整合原 skill-recommender）

- **自动触发时机**：
  - 用户提出的问题或任务可能受益于专业技能；
  - **本地已安装的技能均不适合处理该问题**（本地技能始终优先匹配）；
  - 远端平台（公开或企业源）存在可能更好处理该请求的技能。
- **推荐与预览流程**：
  1. **意图分析与匹配**：结合用户问题中的关键词、专业术语与任务类型，在各源候选结果中匹配，推荐最多 Top 3 最相关选项。
  2. **向用户展示选项**：以清晰列表展示技能名称与简要说明，询问用户是否需要安装。
  3. **安装前详细预览**：用户选定后，执行安装前预览（提取技能名称、描述、功能概览、目标环境与安装路径），等待用户明确确认。
  4. **统一规范安装**：用户确认后，包文件下载至临时目录解压核验（支持 `scripts/preview_skill.py` 辅助预览），经由 `skillshare install` 规范导入至主仓库对应分类子目录中，并执行分发同步。

| 来源 | 适用场景 | 与其他来源的关系 |
| --- | --- | --- |
| skills.sh | 公开技能索引、按关键词发现 | 常指向 GitHub，与直接 GitHub 搜索可重复 |
| GitHub / skillshare Hub | 查源码、补搜仓库、指定团队索引 | Hub 是索引，不是另一个安装目标 |
| OpenAI 官方目录 | 明确要官方精选或实验技能 | 属于 GitHub 来源的一个子集 |
| OneSkill | 企业平台的自然语言推荐、关键词搜索 | 与公开源可能交叉；与旧内网目录是否同库未确认 |
| 已配置的旧内网目录 | 保留原推荐器的目录和下载地址查询 | 保留为独立适配，不假定已被 OneSkill 覆盖 |

命令、返回字段与来源依据见 [发现来源与安装流程](references/discovery-sources.md)，只读所用来源的部分。搜索本身不安装；用户已明确选定并要求安装时，继续执行，不重复询问已给出的授权。

候选按规范仓库及技能子目录、平台及平台 ID、可核验的相同下载对象去重；不能只因名字相同就合并。合并候选保留所有发现来源与版本信息。签名 URL 变化不能作为新技能的依据；无法核验两条记录相同时保留区分。先阅读候选入口、支持文件和依赖，再推荐与需求匹配的结果；来源失败或空结果如实报告，不声称已完成全网搜索。

## 统一安装路径

搜索工具只负责发现和取得来源，不直接向 Codex / Claude 等目标写入。公开仓库与已解包的技能目录都通过 `skillshare install` 安装到当前 `sources.skills`，之后预览并同步。具体子目录、分支、包版本和来源登记与选定候选一致。

平台 ZIP 先下载到临时目录，确认包中唯一目标技能的 `SKILL.md` 位于该技能目录第一层，检查解压成员无路径越界或符号链接后再解包；保留完整脚本、资源和许可。使用 `skillshare install <已解包的技能目录> -g --name <技能名> -s <技能名>` 导入，按 README 记录真实平台来源；临时解包目录不能充当长期更新源。

同名已安装项先比较，保留本地定制，不沿用旧安装器的“先删目录再覆盖”。安装使用明确的仓库、子目录或 `-s` 选择；本机 `--json` 会隐含 `--force --all`，不可仅为非交互输出而使用它；`--force` 也会绕过审计阻断，不能把它当作普通的确认开关。已明确覆盖的情形按实际授权和审查结果处理。

完整外部技能和多段组装继续遵循下方约定；不要再用其他包管理器向目标目录写入另一份副本。系统自带的 Codex skill-installer 不纳入个人库移除范围；需要其下载功能时使用 `--dest <临时目录>`，核验后仍经上述统一路径导入。

## 用户说“更新 skills”时

默认含义是：**查找各技能的 GitHub 出处，获取并合并上游更新，再同步 song-skills 仓库与本机工具目录。** 用户只指定部分技能时，限定在该范围。

1. 先读取主仓库 README 的“技能出处”表，以及相关技能的 `SKILL.md`、README、安装元数据或来源记录。为每个待更新技能确认上游仓库和具体子目录；有疑问时联网核对。
2. 对已有可靠出处的技能，获取上游最新版本，在临时目录比较完整技能目录，包括脚本、参考文件、资源和许可证。单个仓库内可能有多个技能，只更新对应部分。
3. 合并上游改动，保留个人定制、中文适配、工具兼容修改和本地配置。能找到旧上游版本时做三方比较；缺少基线时先审阅差异，不整目录强制覆盖。某个技能冲突无法可靠处理时，保留该技能并报告，继续处理其他技能。
4. 更新主仓库中的技能文件及出处说明。记录实际采用的上游分支或提交、子目录和保留的本地适配；只有核实并采用过的版本才能写成“已更新”。
5. 检查差异、入口与引用、支持脚本等受影响内容。仅提交本次修改，并推送到主仓库配置的远端；不得把其他任务的未提交修改或本地专用文件一起发布。
6. 先运行 `skillshare sync -g --dry-run` 检查，再运行 `skillshare sync -g` 分发到当前配置的目标；读取同步结果并验证关键目标文件。
7. 汇报已更新、已是最新、无可靠出处、无法访问或存在冲突的技能，以及 Git 提交/推送和目标同步的实际结果。

在 song-skills 中执行 `git pull` 只取得个人仓库中的版本；`skillshare sync` 只分发本地文件；二者都不能单独算作完成“更新 skills”。`skillshare update --all` 只覆盖可追踪的远程安装项；即使技能被标为 `local`，只要有可靠的上游来源，仍需逐项比较更新。

若用户只说“同步到 Codex/Claude”等目标目录，执行分发即可。若用户只要求修改规则、合并或移除技能，完成相应本地修改与目标分发，不据此启动全库上游更新或远端提交、推送；已有明确的仓库同步授权时按该范围执行。

## 在 GitHub 介绍中登记出处

在 `song-skills` 根目录 `README.md` 的“技能出处”表中维护：**技能名、来源链接、来源关系与更新注意事项**。GitHub 链接优先指向具体技能子目录；非 GitHub 来源保留真实链接。

- 有证据才写出处：可依据原作者声明、安装元数据、项目说明或已核验的上游文件。依赖库、示例仓库、讨论中提到的项目不能直接充当技能来源。
- 区分直接引入、翻译/移植/改编，以及只封装外部项目的个人技能。多个来源分别署名；改编技能需要合并更新，不能用原版直接替换。
- 未确定来源时标为“待确认”或暂不纳入表中；不能因为缺少链接就认定是个人原创。已经确认由用户编写的技能可标为“个人编写”。
- 安装新技能或确认旧技能出处时，同时维护表格；已有来源字段与表格保持一致。仓库迁移时保留原始出处并补充新地址。

## 安装与组装

完整外部技能先确认来源；分多条消息提供的技能按用户指定相对路径组装，等用户发完后再同步，除非明确要求增量安装。主入口内容符合规范且用户意图明确时，可将 `skills.md` 规范为 `SKILL.md`。

安装与目标配置见 [组装和同步流程](references/skillshare-workflow.md)。涉及上游更新、个人远端仓库与本机分发的区别时，见 [来源更新与仓库同步](references/skillshare-cloud-sync.md)。

## 结果核验

- `skillshare` 是 Go 单文件 CLI，不是 npm 上的同名包；安装命令以项目说明和当前 CLI 帮助为准。
- 当前配置决定同步目标；不能假定一定有 Hermes，也不能把 `0 targets` 或失败输出称为安装成功。
- 区分“上游已更新”“个人仓库已推送”“目标目录已同步”，只报告实际完成的步骤；按需报告版本、提交、目标和同步数量。

## CLI 模式与可恢复移除

已配置的个人库使用 `-g`，从当前配置读取真实源目录；项目的 `.skillshare/config.yaml` 使用 `-p`。不要为了维护已有库重新初始化。

合并技能时先迁移独有规则、参考资料和署名，再用 `skillshare uninstall <旧技能名> -g --force` 移除旧入口；普通卸载同样先检查技能间引用，并清理目录索引和实际转交关系。此命令移入回收区，保留 7 天；需要恢复时使用 `skillshare trash restore <技能名> -g`，然后重新同步。不用 `rm -rf` 删除目标符号链接。

执行安装、卸载或目标变更前先查看适用命令的 `--help` 或使用 `--dry-run`。自动化调用使用明确参数，避免交互提示；不要为跳过提示而扩大安装范围或覆盖无关本地修改。完成变更后预览并执行同步，核对新入口存在、旧入口移除以及其他技能保持完整。

# Case study: game-inspired Japan guide

A useful pattern for a game-inspired travel request:

- Capture the game titles explicitly (`Yakuza 0/7/8`), origin, holiday window, party size, budget posture, duration flexibility, and exclusions (e.g. no Kyoto/history, no forced seven days).
- Order the artifact as requested: ranked real-world places first, ranked signature foods second, then the day-by-day route with time blocks, transport, lodging, meals, budget, and booking notes.
- Treat Kamurocho, Sotenbori, and Isezaki Ijincho as fictional/adapted districts. Describe Kabukicho/Shinjuku, Dotonbori/Sonezaki/Soemoncho, and Isezakicho/Noge/Kannai as real-world atmosphere/route anchors, not exact one-to-one building matches.
- Prefer an open-jaw route when it removes backtracking. For a 5-night/6-day Tokyo-start plan, Tokyo 3 nights + Yokohama day trip + Osaka 2 nights is usually more efficient than adding a Yokohama hotel; use a Yokohama overnight only when its night experience or airport connection is itself a priority.
- For Chinese National Day travel, state the assumed year and dates in the artifact, qualify hotel/transport prices as date-sensitive, and link official holiday and railway sources. Do not put an international flight on the same day as a long intercity transfer.
- Use one or two signature foods per city, not a checklist of every famous dish. Label optional items and explicitly show what to cut.
- For image-rich HTML, use meaningful alt text, responsive cards, readable contrast, and a single-file output under `work/` by default. Open it through a local server and check the document title, section order, text, links, and every remote image; replace any broken image URL before delivery.

This case is a compact workflow note, not a source for current prices or schedules. Re-check official transport, venue, holiday, and booking pages for each new trip.

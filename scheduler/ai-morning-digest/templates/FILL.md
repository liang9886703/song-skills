# 填模板

左栏文件树（点开只显示一篇）；右栏当前篇大纲。**一篇文章一个 md**：导读 + 命中框架的正文（见下）。不要拆成两个文件。

按信息源建文件夹；根级 `今日.md` 作索引。

桌面 ≥960 三栏；640–959 左栏仍在、右大纲进抽屉；≤639（含 iPhone 17 Pro Max 440 宽）默认只看正文，顶栏「文件 / 大纲」打开左右抽屉。填内容时不必改壳。

## 占位

| 占位 | 内容 |
| --- | --- |
| `{{TITLE}}` | 浏览器标题 |
| `{{LEFT_TREE}}` | `<ul class="tree">`，每个 `a.file` 带 `data-doc="<id>"` 与 `href="#doc-<id>"` |
| `{{DOCS}}` | 多个 `<section class="doc" id="doc-<id>" data-doc="<id>">`；索引篇加 `class="doc active"` |
| `{{OUTLINES}}` | 与 doc 一一对应的 `<div class="outline-panel" data-doc="<id>">`；索引篇加 `active` |

## 单篇结构

非仓库文章按 [`reference/article-summary.md`](../reference/article-summary.md) 写：**导读 + 命中框架的正文**，保留原文主干。GitHub 项目直接按 [taste-project](../../../skills/research/taste-project/SKILL.md) 的适用 reference 生成完整报告并渲染，默认初识整个项目；不要用下面的文章摘要结构替代项目报告。较新的要求以 [SKILL.md](../SKILL.md) 及当前定时任务为准。

1. 标题下一行 meta（源 · 日期）
2. **导读**一到两句：这篇在谈什么话题、作者是提观点 / 给结论及推导 / 给工作流。这一段决定用户要不要细看，必须写。
3. 正文按文章实际有的内容起小节（背景、要解决的问题、核心主张、推导与证据、机制或工作流、作者自己承认的局限），**没有的不写**，也不联网补背景，不替作者补他没写的代价。
4. 文章本身标题好用就直接用原文标题；混乱或空泛时才按框架重建；不确定用原文。
5. 框架盖不住的主干内容单独起小标题。
6. 文末一条原文链接。

面向有计算机基础的读者，避免解释常识。HF 论文简洁说明原文支持的结论、关键验证与边界；项目无论是否命中白名单，都遵循 taste-project，不降成几句结论。失败源说明实际原因。

禁止：以「本文介绍了…」开头、通篇名词要点、逐个复述例子、判断写成「值得关注」。

## 填完自检

```bash
python3 templates/check_report.py <当日>/report.html
```

该脚本仅在用户授权与环境允许时运行；不要因为仓库带有脚本就自动执行。也可独立检查占位符残留、文件树/doc/大纲三处 id、死锚点、引用与渲染，并用受支持的浏览器验证移动布局和交互。

# 填模板

左栏文件树点开只显示一篇，右栏只显示当前篇大纲。**一篇文章一个 Markdown 文件**：导读和完整正文放在同一篇，不拆成两个文件。按信息源建文件夹，根级 `今日.md` 作索引。

本文件只约定填装，不另设文章摘要模板。内容按 [SKILL.md](../SKILL.md) 与 [article-summary](../reference/article-summary.md) 的当前规范生成；用户和当前任务的较新要求优先。历史成品只作版式参考。

## 版式与占位

保持用户指定的三栏样式、浅灰侧栏、白色正文和紫色操作区。桌面 ≥960 三栏；640–959 左栏仍在、右大纲进抽屉；≤639（含 iPhone 17 Pro Max 的 440 CSS 像素宽）默认只看正文，顶栏“文件 / 大纲”打开左右抽屉。

| 占位 | 内容 |
| --- | --- |
| `{{TITLE}}` | 浏览器标题 |
| `{{LEFT_TREE}}` | `<ul class="tree">`，每个 `a.file` 带 `data-doc="<id>"` 与 `href="#doc-<id>"` |
| `{{DOCS}}` | 多个 `<section class="doc" id="doc-<id>" data-doc="<id>">`；索引篇加 `class="doc active"` |
| `{{OUTLINES}}` | 与 doc 一一对应的 `<div class="outline-panel" data-doc="<id>">`；索引篇加 `active` |

`report.html` 是基础布局壳，不是所有现行功能都已实现的成品。保留壳的视觉风格，按 [SKILL.md 第 5 节](../SKILL.md#5-执行与质量检查) 补齐原文入口、术语浮窗、Codex 按钮和复制功能，再验证；不要因旧模板缺少功能就省略。

## 单篇内容路由

| 类型 | 写法 |
| --- | --- |
| 普通非项目文章 | article-summary 基础规范：先读原文，导读概括价值，正文另行展开贡献、方法与证据 |
| 提出一种技术的非论文、非项目文章 | 基础规范加“技术文章专用写法”：问题、思路与机制、实现问题及解决措施、成果和原文明确的规划；不强造论文式实验 |
| 论文 | 基础规范加“论文专用写法”：研究范围、学术价值、问题与出发思路、具体尝试、结果与验证、进一步规划与思考；沿实际论证组织，不照搬空栏目 |
| GitHub 项目 | 直接按 [taste-project](../../../skills/research/taste-project/SKILL.md) 的适用 reference 生成完整报告并渲染，默认初识整个项目；不以文章摘要结构替代 |

标题下先显示来源与日期，并显著放可点击的“原文”链接；项目使用“官方项目”链接。非项目文章保留导读和有充分解释的独立正文，不能把导读拆成短段当正文。自然使用具体小标题，不机械命中旧框架，也不以增加标题代替解释。每篇不超过 4000 中文字，完整保留主要贡献、关键过程、代表性结果和必要条件；给出足够理解的背景，不假设读者熟悉专门领域。

文末保留原文与参考资料；将准确原文 URL 纳入单篇和整期复制文本。填装者只做正确渲染，不再次压缩作者贡献、论文证据或项目报告。来源失败说明实际原因，不能写成“今天没有新闻”。

## 交互与移动端

按 SKILL 第 5 节执行完整要求：

- 正文术语点状下划线，附近可关闭浮窗，支持鼠标、触屏和键盘；不新增独立术语栏，项目名词表仍保留。
- 总览及每篇有“在 Codex 追问本页”，项目另有“在 Codex 深入分析”与复制请求备选。深链接只打开并预填，正确编码日期、标题、当期 URL/锚点或项目地址，不自动发送。
- 每篇可复制正文与引用，总览可复制整期正文；提供可展开的只读文本框，复制失败时展开并选中供手动复制。
- 手机保留缩放、安全区域和约 16–17px 正文字号，输入框至少 16px，按钮触控区至少 44px；长标题、链接、代码不得撑宽页面，表格与代码块局部滚动。
- 文件树与大纲抽屉可开关，关闭后不遮挡正文或保留隐藏焦点；术语浮窗不溢出可视区域。
- 私有 Site 仍需权限与登录。深链接不等于正文已被读取，不把全文或认证令牌塞进链接，不为方便读取而公开站点。

## 填完自检

1. 内容路由正确，主要贡献、关键方法、验证和结果保留；论文与技术文章各自要求未混用，项目报告未被压缩。
2. 每篇标题下原文或官方项目链接正确可点击，文末引用与复制文本一致。
3. 四个占位无残留；文件树、正文、大纲的 `data-doc` 一致，文章及大纲锚点有效，Markdown 链接已正确渲染。
4. 检查每页 Codex 预填内容、URL/锚点、编码、复制正文与引用，以及复制失败的手动备选。
5. 尽力验证 320–440 CSS 像素竖屏和横屏、长标题、表格、横向溢出、文章切换、大纲、抽屉、弹窗与触屏交互。
6. 区分网页行为验证、iPhone 真机测试和用户本机 Codex 打开／读取测试，未做的明确说明。

仓库附带 `templates/check_report.py`，用于占位、ID 与锚点检查，仅在用户授权与环境允许时运行，不因脚本存在就自动执行。也可用独立静态检查和受支持的浏览器验证；该结构检查不能替代内容与交互检查。

# 非项目文章阅读与写作

> 当前规范：按用户截至 2026-11-10 的要求同步。完整替换旧文章总结提示词，不与历史短摘要模板叠加；历史成品只作版式参考。

## 适用范围

- 普通新闻、博客、访谈等非项目文章：使用下文“基础规范”。
- **提出一种技术的非论文、非项目文章**：在基础规范上使用“技术文章专用写法”，不机械套论文实验框架。
- **论文**：在基础规范上增加“论文专用写法”，不套技术文章专用段落。
- **GitHub 项目**：不使用本文，直接读取 [taste-project](../../../skills/research/taste-project/SKILL.md) 及其适用 reference。
- 模型发布新闻保留“发布与使用情况、主打核心能力、其他官方重点”三段。选材、去重、页面、权限和发布仍按 [SKILL.md](../SKILL.md)。

## 基础规范

目标：保留作者实际做了什么、为什么重要、怎样做到、拿什么验证、得到什么结果。精简重复和次要细节，不能精简掉主要贡献、理解方法必需的过程或支持结论的关键实验和结果。导读只承担价值概述，正文必须另有充分展开，不能把导读拆成几个短段当作正文。篇幅服从解释深度：读者应能复述作者如何想到、如何实现、怎样验证、结果为何成立；不能只说做了某实验而不说明对照意图与发现。复杂研究应以连贯的多段正文解释关键机制、训练或执行过程、实验设计与代表性结果，避免每节一两句摘要。无需堆满参数，也不凑字数，但不得以精简牺牲方法和证据。每篇仍不超过 4000 中文字，遵守来源许可和引用限制。

1. 先读原文再选重点。论文读取摘要、引言/贡献列表、方法、实验设置、结果、讨论及局限；博客/访谈按其实际结构阅读。先识别作者明确列出的主要贡献、中心论证及对应证据，逐项检查正文是否保留；不要凭 HF 摘要或二手报道替代正文。原文已清晰总结贡献时忠实转述其重点和逻辑，不为另起框架把它拆散或替换为空泛评价。首次、最佳等优先权主张标为作者自述并限定范围。无法取得关键章节时明确说明，不能假装已读。
2. 导读先回答“讲什么和值在哪里”。交代具体领域/对象、问题或变化、作者此次工作属于发现问题、提出方案、评测方法、数据集或其他何种贡献，并点明其最重要的新认识、做法或结果。必要背景足够理解即可，不假设读者已熟悉专门领域；目标与验证过的效果分开。不要只写适合谁读、术语堆叠或抽象意义。Agent 实际任务执行优化与训练/评测任务生成要区分，按项目实际能力说明，不因名字含 Agent 就归类；示例项目不因此自动入选。
3. 正文沿作者的核心论证展开。把问题如何引出思路、关键设计怎样工作、与已有做法有何实质不同讲清。多项贡献不能只挑一项写；原文有几个重要思路及比较，就保留其关系。过程至少讲清输入、关键变化和输出，必要时选一个原文案例帮助理解，不复刻无关步骤或全部例子。自然使用具体小标题，原文结构清楚就沿用其逻辑，不强套固定栏目；标题让读者看出方法或结论，不能仅写“实验结果”“改善思路”。
4. 保留能判断证据强弱的实验与结果。交代用什么任务/数据/模型或环境、与什么基线比较、测量什么，并解释这些对照在验证什么。保留支撑核心结论的代表性结果、关键幅度和必要数字，不写成只有“更好、更快”。明确输入 token、总 token、时间、正确率等指标的口径，百分比与百分点、相对与绝对变化分清。关键消融若用于解释机制，保留其结论和适用条件；不要把验证方法写成新技术，不把模拟当真实部署，不把相关或假说写成因果。
5. 文章价值从贡献和证据自然得出：它新增了什么认识、方法或可用数据，适用于什么问题和条件，证据不能支持什么外推。局限不盖过贡献，不凭空制造作者未讨论的缺点。区分作者观察、支持的解释、假说和编辑判断；不把目标当已实现收益、不把无显著差异当等价证明。不写对用户个人项目的帮助，不映射用户的个人工作、不推测用户需求。
6. 产品、合作、收购和区域上线报道按实际变化和目的写，不硬造科研问题或收益。模型发布继续采用发布使用情况、核心能力、其他官方重点三段。首发日期、收录日期分开，不用旧消息充当当天首发。
7. 发布前逐篇对照原文做完整性检查：作者的主要贡献是否遗漏？关键方法能否复述？实验比较了什么、结果到底如何是否可见？主要结论的条件是否保留？如果把贡献和实验结果删掉后文章仍能原样成立，说明写得空泛，须重写。保持原文链接、引用和复制内容一致，不以更多小标题代替内容。

## 技术文章专用写法

仅适用于提出一种技术的非论文、非项目文章；不改变论文或 taste-project 规范。以下是按原文核对的问题，不是必须填满的栏目。

先完整阅读原文，沿问题到方案的逻辑讲清：具体要解决什么问题及其背景；解决思路、原理和关键机制怎样工作；实现这一思路遇到哪些问题、为什么出现及怎样解决，包括必要的设计权衡；已经取得什么成果、部署或覆盖到什么范围、有哪些证据；原文明确的进一步规划及其他理解核心贡献必需的信息。以上是需要按原文核对的问题，不是必须填满的栏目，不机械套入论文式实验模板；原文未涉及的困难、实验、成果或计划不要凭空补齐。没有对照实验的技术文章可用架构说明、运行数据、部署情况或原文案例解释实际成果，不把作者陈述当独立验证。分清监控发现问题、作出停止决定和系统执行控制等不同环节；定量指标保留起止点、口径、适用范围与限制，系统覆盖状态和后续计划注明文章发表时点，不把未来目标写成已实现。导读说明文章讲什么、重要的新做法或结论，正文另行解释必要的因果链和证据。发布前逐篇对照原文核查核心问题、思路与机制、解决措施、成果和规划是否准确完整；不以空泛评价或更多小标题替代内容，原文链接、页面正文及复制文本保持一致。

## 论文专用写法

仅用于论文，在基础规范上增加，不用于项目、普通新闻、博客或访谈。

先阅读论文原文，再依据作者实际研究内容生成导读与独立展开的正文。下面六项是需要回答的问题，不是强制照搬的六个空栏目；沿论文真实的贡献和论证组织，使用具体小标题，不把机制、结果与进一步思考混成一段。导读概括这些要点，正文再充分解释，不以导读替代正文，也不把导读扩成没有层次的长摘要。

导读部分要让读者看清：
1. 研究范围：这篇文章属于模型训练、大模型评测、Agent 评测、Agent 框架或其他什么具体领域，研究对象和任务是什么。按实际工作准确归类，可说明交叉范围，不因名称含 Agent 就归类。
2. 对学术界的价值：具体新增了哪种知识、方法、理念、资源或证据。例如是一套模型评测集制作方法、一种评测集设计理念，还是一套针对特定任务的评测集；这些示例用于辨清贡献，不把不同贡献混为一谈，也不要求每篇都属于其中一类。保留原文列明的主要贡献，避免泛泛说“推动发展”。
3. 问题与出发思路：文章发现了什么问题，或选择在哪个环节发力；已有做法有哪些与本次研究直接相关的不足，作者基于什么观察、假设或思路开展这次尝试。明确哪些已被发现，哪些仍是假设。
4. 具体尝试：概括作者实际做了什么，以及关键环节如何衔接来完成这次尝试。
5. 结果与验证：点出最重要的发现或结果，并交代用什么实验、比较、分析或其他证据验证，不能只报结论不说依据。
6. 进一步规划与思考：概括原文明确提出的后续研究、未解决的问题或进一步讨论。原文未明确提出后续规划时如实说明，不替作者编造计划；如补充基于文中证据的编辑思考，须明确区分作者原意和编辑判断。

正文在导读之外沿核心论证充分展开：
- 将研究问题如何引出本文思路讲清，说明这项学术贡献相较已有研究具体新增了什么。不是罗列标签，也不转成对用户个人项目的帮助。
- “具体做了什么”可按研究的多个关键环节拆成多个有信息量的小标题。逐环节说明要解决什么、输入是什么、采用什么思路或设计、得到什么输出、为何这样安排，以及如何衔接下一环；重点介绍思路与必要机制，不要求复刻全部实现细节、代码、公式或参数。多项主要贡献及其关系都要保留，不为精简只挑一个亮点。
- 结果与验证另行讲清：使用什么任务、数据、模型或环境，与什么基线或对照比较，指标衡量什么、每个关键实验要验证什么、实际发现什么。保留代表性结果、关键数字、适用条件和用于解释机制的关键消融，说明证据支持到什么程度。非实验型论文按其实际证明、分析或论证方式说明依据，不强造实验。
- 进一步规划与思考与已验证结果分开：忠实整理作者明确提出的未来方向、讨论及尚未解决的问题；区分作者计划、作者推测、证据支持的结论和编辑思考。没有原文依据的未来规划不填造，局限也不能盖过贡献。
- 发布前逐篇核对上述六个问题是否都有依据且被回答；尤其检查研究范围与学术贡献是否具体、问题到方法的逻辑是否连贯、各环节是否足以理解思路、结果和验证是否对应、未来规划是否确有原文支持。继续遵守每篇不超过 4000 中文字、完整原文阅读、主要贡献与关键证据不遗漏、来源许可、原文链接、引用及复制一致性等所有既有要求。
